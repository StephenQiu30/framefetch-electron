# 产品定位与功能范围

## 1. 产品目标

帧取桌面端是一款个人视频工作站：用户安装应用，选择本地工作目录，即可导入媒体和剧本、下载经过验证的平台视频、跟踪任务、播放本地文件、发起可选 AI 分析并保存报告。

应用不要求 FrameFetch 账号、服务器地址、Docker、数据库服务或项目源码。操作系统账号是本地数据边界；平台账号与模型凭据属于用户另行配置的外部能力。

现有 Web/App 的业务概念和视觉语言可复用，桌面端重新承担本地执行、文件所有权和恢复职责。首版不搬入多用户管理、云端配额、MinIO、运营统计或部署管理界面。

## 2. 如何判定“高度独立”

| 维度 | 可判定要求 |
| --- | --- |
| 安装独立 | 完整安装包包含必要运行时；用户无需另装 Node、Python、FFmpeg 或 Docker |
| 启动独立 | 不配置 `video-server` 地址、不检查自有服务健康、不要求登录即可进入本地工作区 |
| 数据独立 | 数据库、媒体索引、任务、报告和设置保存在本机，基础业务不使用 PostgreSQL/MinIO |
| 执行独立 | 下载、probe、哈希、抽帧、文档解析在本机运行，主窗口保持响应 |
| 构建独立 | 仅 checkout `video-electron` 即可构建，不引用 `../video-server` 或 `../video-app` |
| 分发独立 | 安装包可离线传递和安装，更新服务关闭或不可达时仍可使用 |

| 功能 | 断网时行为 |
| --- | --- |
| 本地媒体/文档导入、元数据、索引、播放 | 可用，前提是源文件仍在本机且编码受支持 |
| 历史、已保存分析、报告导出 | 可用 |
| 网络平台解析和下载 | 显示网络错误，保留历史和任务事实 |
| 用户配置的云端 AI | 不可执行新调用，已有结果仍可读 |
| 后续本地 AI | 模型已就绪且满足设备要求时可用；需要单独验证完全断网条件 |
| 更新检查 | 失败不影响工作区，无强制升级 |

## 3. 首版闭环

首版必须在 macOS 与 Windows 的已安装应用中完成以下闭环，不能仅在开发模式中演示：

1. 首次启动，选择媒体保存目录，直接进入工作区。
2. 拖入本地 MP4，完成流式哈希、ffprobe、封面、媒体登记和播放。
3. 粘贴一条通过验收的公开平台链接，解析元数据、选择语义规格、下载、验证完整文件并打开保存位置。
4. 任务执行时取消；取消确认后无残留媒体子进程。退出并重启后历史、文件和任务状态一致。
5. 导入 TXT/Markdown/Fountain、文字型 PDF 或 DOCX 剧本文档，查看提取结果。
6. 可选配置自己的模型 API，对本地视频或剧本完成一次真实分析，读取结构化报告并导出 Markdown/DOCX。

未配置 AI 不阻塞媒体业务。模型调用失败不改变已经成功的下载状态。

## 4. 功能分期

| 能力 | 首版 v0.1 目标 | 后续 v0.2 / v0.3 |
| --- | --- | --- |
| 本地工作区 | 目录、最近内容、主题、原生打开/保存 | 多工作区仅在有真实需求时增加 |
| 媒体导入 | MP4；引用或托管复制；封面、元数据、hash、缺失检测 | 更多容器、拖入多文件、自动整理 |
| 文档导入 | TXT、Markdown、Fountain、文字型 PDF、DOCX | OCR、扫描 PDF 不在当前计划 |
| 平台下载 | 受限平台清单、公开非 DRM 单视频、格式选择、完整校验 | 登录平台、来源发现、受限批量任务 |
| 平台首批候选 | Bilibili 公开单视频、YouTube 公开单视频；另外用受控 HTTPS MP4 做确定性下载验收 | 首版至少一个真实平台通过；另一候选若未通过，不在支持清单中展示为可用 |
| 任务中心 | 下载/导入/分析状态、取消、有限重试、重启协调、并发限制 | 批量编排与更细的资源策略 |
| 媒体播放 | 经确认的 MP4/H.264/AAC；证据时间跳转；不支持时可调用系统播放器 | WebM/VP9/AV1 等按安装包矩阵扩充；必要时生成独立预览文件 |
| AI 分析 | 自备模型 API；能力检测；精选内置 Skill；结果校验 | 已有 Ollama 等本地模型连接、更多经过验证的模型适配 |
| 首批 Skill | 综合视频、分镜、高光、视频转文章、剧本分析/改写 | 其余 Skill 分批迁移，不接受任意用户代码插件 |
| 报告 | 本地查看，Markdown/DOCX 导出，结果版本关联 | 其他格式按需要增加；PDF 不是首版硬要求 |
| 系统体验 | 拖放、键盘导航、原生目录选择、任务完成通知、Finder/资源管理器定位 | 托盘、关闭窗口继续运行、更新检查 |
| 分发 | macOS DMG、Windows 完整 NSIS 安装包、手动覆盖升级 | 可关闭自动更新、可选浏览器资源包 |

YouTube 的 JS proof、PO Token、网络出口和浏览器依赖按实际样本验证。安装包带有 yt-dlp 或平台名称，不等于平台下载已通过。首版不承诺服务端现有全部平台可用。

内容范围优先迁移服务端的 `public` 规则：公开、免费、非 DRM、用户有权获取的媒体。腾讯/优酷的 `personal_full` 属于后续平台专项，不因读取账号材料自动启用；保护内容提供本地文件导入入口。

## 5. 桌面信息架构

| 一级入口 | 用户任务 | 关键交互 |
| --- | --- | --- |
| 工作区 | 粘贴链接、拖入文件、选择格式和保存位置 | 输入后就地展示结果，不跳转到服务器页面 |
| 任务 | 查看队列与进度、取消、重试、恢复 | 区分解析、下载、合并、校验、分析阶段；无法量化时不伪造百分比 |
| 媒体库 | 搜索本地文件、播放、定位、查看分析 | 列表与详情；播放器和证据时间轴联动 |
| 剧本与报告 | 导入剧本、发起分析、阅读及导出 | 源文档和结果关联；缺失来源不删除已有报告 |
| 设置 | 保存目录、磁盘缓存、并发、模型、版本诊断 | 功能就绪按当前设备和真实配置显示 |

延续 Web 的黑白灰、中性色、低密度布局和可访问控件。桌面提供侧栏、窗口标题区域、快捷键和原生对话框；不复制移动导航或 Web 管理中心。首版以中文为主，同时建立文本资源入口，避免后续本地化逐页重写。

## 6. 首次使用与应用退出

首次启动只要求确认媒体目录；AI Key 与平台会话按功能需要配置。启动诊断失败时显示具体缺失资源和可采取的操作，不能要求用户安装开发工具。

首版关闭主窗口视为退出应用：停止接收新任务，有限排空或取消本地进程，保存中断事实。活动任务存在时提供明确的退出提示。不会宣称应用退出后仍能下载；托盘后台能力单独开发和验收。

默认不随系统启动、不自动上传诊断、不自动读取剪贴板或全盘扫描。粘贴、选择文件、导出和发送到 AI 均由用户的相应操作触发。

## 7. 本地模型的产品边界

后续优先接入用户已经安装的本地模型运行时，而非首版内置几十 GB 模型和 GPU 栈。本地模型不保证与云端模型同等效果；视频分析要求视觉输入能力，纯文本模型只能用于相应剧本和文本 Skill。

Ollama 等运行时既可能调用本地模型，也可能使用云端模型。只有核实选用本地模型并完成阻断外网的验收，才可标注“离线 AI”；`localhost` 地址自身不能证明没有外部调用。其接口依据 [Ollama 官方说明](https://docs.ollama.com/api/introduction)。
